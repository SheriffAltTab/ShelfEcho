## Тест-план + звіт (System): реєстрація/авторизація/рекомендації

### 1. Мета
Провести системне тестування локального застосунку як «чорної скриньки» через HTTP API, з фокусом на:
- **Функціональне тестування** (обов’язково)
- **Тестування безпеки** (обов’язково)
Додатково (популярні типи): базова надійність, сумісність конфігурацій, базова продуктивність.

### 2. Передумови та оточення
- Локальний запуск сервера.
- SQLite БД (локальний файл).
- Для системних перевірок SMTP **може бути вимкнений**, якщо запуск робиться з `NODE_ENV=test` (у такому режимі реєстрація не потребує email-верифікації).

### 3. Обсяг
Тільки:
- Реєстрація
- Авторизація (email+password)
- Рекомендації
- Favorites як фактор, що впливає на рекомендації

### 4. Поза обсягом
- Google OAuth
- Реальна доставка листів (SMTP), перевірка поштової скриньки
- UI/клієнт

### 5. Тестові сценарії (чекліст)
#### 5.1. Функціональні
- **S-FUNC-01**: Реєстрація валідними даними → 201.
- **S-FUNC-02**: Логін тими ж даними → 200 + `token`.
- **S-FUNC-03**: `/api/auth/me` з токеном → 200 + профіль.
- **S-FUNC-04**: Онбординг жанрів (`Fantasy`, `Mystery`) → 200.
- **S-FUNC-05**: Featured recommendations → 200, список не порожній (або коректно порожній, якщо немає джерела), subjects перетинаються з жанрами онбордингу.
- **S-FUNC-06**: Додати 10 книг у Favorites (різні жанри) → 201/409, після цього recommendations змінюються (набір ключів/порядок).

#### 5.2. Безпека
- **S-SEC-01**: `/api/auth/me` без токена → 401.
- **S-SEC-02**: `/api/recommendations/featured` без токена → 401.
- **S-SEC-03**: Логін з неправильним паролем → 401.
- **S-SEC-04**: Повторна реєстрація з тим самим email → 409.
- **S-SEC-05**: Токен з підробленим підписом → 401.

#### 5.3. Інші популярні типи
- **S-REL-01 (Надійність)**: recommendations не падають при пустому shelf (без reading_list/favorites).
- **S-COMP-01 (Сумісність)**: поведінка при `NODE_ENV=development` vs `NODE_ENV=test` (в test — без email-верифікації).
- **S-PERF-01 (Базова продуктивність)**: featured recommendations відповідають за прийнятний час локально (орієнтир: < 2с при стабільних даних).

### 6. Процедура виконання (ручна)
З каталогу `server/`:

```bash
# Варіант A (без SMTP, для локального системного прогону)
$env:NODE_ENV="test"
npm run dev
```

Далі виконати запити (Postman/Insomnia/curl):
- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me` (Bearer token)
- `PUT /api/user/onboard`
- `GET /api/recommendations/featured`
- `POST /api/favorites` (10 разів)
- `GET /api/recommendations/featured` повторно
